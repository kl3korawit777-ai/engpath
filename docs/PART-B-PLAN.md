# แผน Part B — ย้ายแอปมาใช้คลังคำกลาง (/vocab)

สถานะ: Part A เสร็จ (5,050 คำ, `vocab/` build แล้ว v1.0.0) · เอกสารนี้คือแผนก่อนลงมือ

## หลักการออกแบบ (ขอให้ยืนยัน)
1. **คลังเป็นข้อมูลอ่านอย่างเดียว** โหลดจาก `/vocab` (index.json + level-NN.json) cache ด้วย service worker; ไม่ใช้ API ภายนอก/Claude API สำหรับหาความหมายอีก
2. **Firestore เก็บเฉพาะความคืบหน้า** อ้างคำด้วย `wordKey` ของคลัง
   - ใช้ collection `cards` เดิม โดย **`id = wordKey`** และเก็บเฉพาะ `{wordKey, level, status, addedAt, note, skipped}`
     (ไม่เก็บ en/th/example ซ้ำ — อ่านจากคลัง) → `reviews`/SRS เดิมใช้ต่อได้โดยไม่แก้ตรรกะ
   - ความคืบหน้าเป็น doc ต่อคำ ใต้ `users/{uid}/cards/{wordKey}` (ผู้ใช้หลายคน แยกกันด้วย path อยู่แล้ว)
3. **ผู้ใช้เพิ่ม/แก้คำไม่ได้** ลบหน้า “เพิ่มคำ”, `lexicon.js` ส่วนเรียก API, `wordlookup.js`, ช่อง API key สำหรับคำศัพท์ (Claude key ยังเหลือใช้กับ Journal ตรวจ)
4. **โน้ตส่วนตัวต่อคำ** เก็บใน `cards/{wordKey}.note` รองรับลิงก์ `[[ ]]` (ใช้ `links.js`/`graph.js` เดิม)

## ประเด็นที่ต้องรู้
- **`tools/` ถูกเสิร์ฟโดย GitHub Pages** ถ้า push ทั้ง repo (ขัดกับกฎ “ห้าม deploy tools”) ทางแก้: ย้ายไปเผยแพร่ด้วย GitHub Actions เฉพาะไฟล์ของแอป (`index.html css js vendor icons vocab …`) — ทำใน B9 และต้องให้คุณตั้งค่า Pages ให้ใช้ Actions
- ความหมายที่ฉัน (Claude Code) เขียนเอง ~3,000 คำ ถูกติดป้าย `claude` ในรายงานแล้ว; มี `overrides.json` สำหรับให้คุณแก้ได้โดยไม่ต้องรันใหม่ทั้งชุด
- งานนี้แตะไฟล์จำนวนมาก (ดู `grep lexicon` ~28 ไฟล์) จึงแบ่งเป็นขั้นและรัน `npm test` ทุกขั้น
